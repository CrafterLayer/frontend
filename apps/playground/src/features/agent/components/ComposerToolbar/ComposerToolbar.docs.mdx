# ComposerToolbar

The composer's bottom row (SPEC §4.17): Mode ▾ and Model ▾ at the inline start; ✨ Improve, `[@]`
and the Send slot at the inline end.

<Canvas of={ComposerToolbarStories.Ready} />

## Purpose

Read in the order a request is made: how it may touch the page, who writes it, then the tools for
the words, then Send, the last thing the hand reaches. A control with nothing to offer is absent,
never dead: one model means no ModelMenu, no rewriting means no ✨.

The folder also holds the pieces ModeMenu and ModelMenu share: `ChoiceMenu` (a ghost trigger over a
Radix DropdownMenu radio group of two-line items) and `ComposerTooltip` (IconButton's tooltip for
labelled triggers: Stop, Send, ✨ and the menu triggers).

## Anatomy

32px items with 4px between them, 4px under the text; 44px items 8px apart under a coarse pointer
(SPEC §2.3, §6.4). The target size and gap are inherited custom properties (`--ck-agent-target`,
`--ck-agent-toolbar-gap`), set by the stylesheets only under `(pointer: coarse)`, so the phone sheet
or a story can preview them from an ancestor.

Both the choice group and the action row may wrap; neither can push a control outside the panel.
Provider labels use a shorter visual measure below 360px. Accessible button names retain the full
label, and menus remain portalled above the composer rather than clipped inside a scroll box.

## Accessibility

- Every control is in the tab order, in reading order; the worker pool uses a labelled native
  select.
- The mode trigger is never disabled: a mode chosen while running applies to the next request.
- The pool offers one, three, or six workers for independent build sections, not multiple writers on
  one edit. It is disabled throughout a live run and while improving the draft.

## RTL

The choices at the right, the actions at the left, by `justify-content` and logical margins.

## Motion

None of its own; its menus open with SPEC §5 moment 9.
