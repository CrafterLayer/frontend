# SkillSlash

The composer's `/` (2026-10-12): a slash at the start of the message or after a space lists the
skills, and picking one pins it to the next message.

<Canvas of={SkillSlashStories.Open} />

## Purpose

People who use other agents expect `/` to reach a skill by name. A pinned skill is an explicit
choice: the Agent must use it for that message, whatever the request's words say. The list shows the
person's own enabled skills first, then the built-ins, and ends with "Manage skills & memory". The
words after the slash narrow it: `/brand` finds Brand voice, and «اسلوب» finds «أسلوب المنزل». A
picked skill leaves the draft and sits above the composer as a chip with ×, until the run it went
out with ends.

## When to use / not

AgentPanel draws it above the Composer when the host gives the panel its `knowledge`. It needs the
composer's textarea (`inputRef`). That textarea keeps focus throughout and serves as the list's
combobox, as it does for the `@` list. It reads and pins through `knowledge.skills` (`pinned`,
`pin`, `unpin`); `useReleasePinsAfterRun` lets the pins go after the run. To write or change skills,
use the Skills tab (KnowledgePopover), which "Manage skills & memory" opens.

## Props

| prop            | type                                     | default | notes                                                |
| --------------- | ---------------------------------------- | ------- | ---------------------------------------------------- |
| `locale`        | `Locale`                                 | none    | picks `knowledgeLabels(locale).slash`                |
| `skills`        | `UserSkillsView`                         | none    | the person's skills, the built-ins, and the pins     |
| `draft`         | `string`                                 | none    | the composer's draft: a `/words` at its end opens it |
| `onDraftChange` | `(draft: string) => void`                | none    | a pick takes the `/words` out                        |
| `inputRef`      | `RefObject<HTMLTextAreaElement \| null>` | none    | the composer's textarea: keys, focus, combobox state |
| `onManage`      | `() => void`                             | none    | opens Skills & memory                                |
| `commands`      | `readonly SlashCommand[]`                | all     | which commands to offer                              |
| `onCommand`     | `(command, text) => Promise<string?>`    | none    | runs one; without it the list offers no commands     |

The model is pure and table-tested: `slashToken`, `withoutSlash`, `commandOf`, `slashOptions`,
`slashCommands`, `textBeforeSlash` and `MAX_PINNED_SKILLS` (3) in `model/skill-slash.ts`.

## Commands

Above the skills, three commands act on the words typed before the slash. AgentPanel runs them
through `useKnowledgeUi`:

- **Remember** (`/remember`, `/تذكر`) keeps the words in the project memory as a preference. With no
  words it opens the Memory tab. A repeat is refused, as the tab refuses it.
- **Save a checkpoint** (`/checkpoint`, `/نقطة`) keeps the page under the words, or under the
  default name. It is offered only when the host keeps pages.
- **New skill** (`/skill`, `/مهارة`) opens New skill on the Skills tab with the words as its
  instructions.

The words leave the composer with the slash. What happened is said once in a `status` line under the
list, which clears after four seconds.

The list floats 8px above the composer (e2, radius 9) and shows seven rows before it scrolls (four
on a finger). On the active row the description steps up from Graphite to the soft text colour,
which keeps it at 4.5:1 on the wash.

## Accessibility

- The composer's textarea is the combobox. While the list is open it carries `aria-expanded="true"`,
  `aria-controls` (the listbox) and `aria-activedescendant` (the active option). They are set on the
  element directly and removed when the list closes.
- The list is a `listbox` named "Skills". Each skill is an `option` with `aria-selected`. The two
  headings are drawn (`aria-hidden`, `role="presentation"`), never read as options.
- Keys go to a native listener on the textarea, so the composer never sees them while the list is
  open: ↑ ↓ move (wrapping), Enter or Tab pick, Esc closes the list for that draft. The next letter
  typed opens it again. A click picks without taking focus from the textarea.
- A refused pick (the message already holds three) is said in a `status` line. The line is in the
  tree whenever the list is open, so filling it is announced. It clears with new words or a new
  list.
- The chips are a `group` named "Skills for the next message"; each × is named "Remove {name}" and
  returns focus to the textarea.

## RTL

Logical properties only: the list and chips start at the inline start, and the active bar mirrors.
Commands stay left to right (`dir="ltr"`, `<bdi>`). Names and descriptions run in their own script's
direction. Search folds case, hamza, taa marbuta and alef maqsura.
