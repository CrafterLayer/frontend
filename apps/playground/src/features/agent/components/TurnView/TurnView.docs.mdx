# TurnView

A turn, drawn as its record or card (SPEC §7.2 #50): the one place that knows which component
draws which of the nine v2 turn kinds.

<Canvas of={TurnViewStories.Build} />

## Purpose

AgentThread owns the `<li>` around each turn, keyed by its id; TurnView fills it. A turn that
changes kind (a plan becoming its build, a proposal its edit) keeps its node, so focus sent to the
new record's head finds it.

| kind        | component    |
| ----------- | ------------ |
| `user`      | UserMessage  |
| `build`     | BuildRecord  |
| `edit`      | EditRecord   |
| `answer`    | AnswerRecord |
| `page-plan` | PagePlanCard |
| `step-plan` | StepPlanCard |
| `proposal`  | ProposalCard |
| `error`     | ErrorRecord  |
| `end`       | EndNote      |

## Props

| prop             | type                             | default | notes                                                  |
| ---------------- | -------------------------------- | ------- | ------------------------------------------------------ |
| `locale`         | `Locale`                         | none    |                                                        |

| `hideFollowUps`  | `boolean`                        | `false` | hides a first build's next-step chips (run live, words in the box) |

## Next steps after a first build

A build whose view carries `nextSteps` (the newest turn, a first build that finished on an empty
page; `turnViewsOf` decides) draws FollowUpChips under its record: «بدّل الألوان», «ستايل مختلف»,
«رتّب الأقسام», «أضف قسمًا». A chip sends its request through the typed path, `setDraft(request)`
then `send()`, so it is routed and runs the ordinary edit flows. AgentPanel passes `hideFollowUps`
while a run is live or the composer holds words, so a chip never sends over a request being written.

## The record menu

`[⋯]` items run here (`runMenuItem`) and never post text as the person's turn: Reuse request puts
the request back in the composer and focus with it; Copy summary, answer and error details go to the
clipboard through the controller; View as code and Technical details go to the host; Restore page
opens RestoreDialog over the record, returning focus to `[⋯]`, and restores only on its confirm.

## Accessibility

Each component brings its own structure (an `<article>` named by its `h3`, `tabindex="-1"`).
TurnView adds nothing to the tree but the dialog Restore opens.
