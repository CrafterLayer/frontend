# SiteBriefForm

One sentence in, a whole site out.

<Canvas of={SiteBriefFormStories.Empty} />

## Why an Action rather than a click handler

The two things a person needs from a form while something is happening — that it is happening, and
that it must not be started twice — are exactly what React's `useActionState` reports, and it
reports them from the promise itself. Deriving the same two facts from a `useState` boolean means
owning every path that must clear it, and one missed path leaves a form that never unlocks again.

## The Action ends at ADMISSION, not at completion

`onSubmit` resolves the moment the run is accepted or refused — never when it finishes. This is not
a shortcut, it is forced: every state update made inside an Action is a **transition** update, and
React holds the re-render until the action settles. A host that awaited a five-stage site build
here would have held its own progress card for the whole build — five stages, minutes long, and not
one frame of it visible until the moment it was already over. That was written first, and the
progress card provably never appeared.

So a reason shown here is a reason the run could not START. A stage that fails three minutes later
belongs to whatever is showing the run: by then the sentence in this field is not what went wrong.

<Canvas of={SiteBriefFormStories.Submitting} />

The pending state is announced in a polite live region rather than through the button's changing
label. A label on a **disabled** control is not reliably announced, and "it is working" is the one
thing a person waiting on five stages must not have to guess.

## A refusal is not an error

<Canvas of={SiteBriefFormStories.Refused} />

A blank brief is the form declining to start a run: no spinner, no entry in history, nothing to
undo. The field is marked `aria-invalid` and the reason is tied to it with `aria-describedby`, so
a screen reader hears why the moment focus returns.

<Canvas of={SiteBriefFormStories.Errored} />

An error is different: a run **did** start and came back with a reason. The field is not marked
invalid — nothing about the sentence was wrong — and the sentence is kept. The field is
uncontrolled, so React would clear it on submit; keeping it is a decision, because losing what
someone typed in order to tell them it did not work would be its own small insult.

## What it does not decide

The form neither builds nor commits. It hands a trimmed brief to `onSubmit` and reports what comes
back. Which provider runs, whether the result lands on the live site, and what a person sees while
five stages go past all belong to the panel that composes it — this stays one control with one job.

<Canvas of={SiteBriefFormStories.Arabic} />

Arabic is the default locale, and the field is `dir="auto"` in both: a person writing Arabic into
an English-chrome panel should see their own text run the right way without changing a setting.
