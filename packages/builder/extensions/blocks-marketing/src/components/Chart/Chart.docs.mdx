# Chart

A data chart drawn as hand-built, accessible SVG: bar, horizontal bar, line, area, combo, scatter,
radar, funnel, gauge, sparkline, pie, donut, waterfall, heatmap, treemap, histogram, bubble,
boxplot, candlestick, lollipop and bullet. It needs no chart library and no client script, so the
published page shows the same picture the canvas does.

## Content model

- `title` and `description` (both optional) form the `<figcaption>`. The title names the picture
  (`role="img"`, `aria-labelledby`); the description is its accessible description. An untitled
  chart is named by its series.
- `chartType = 'bar'`, one of:

  | type          | use it for                                     | draws                                                                 |
  | ------------- | ---------------------------------------------- | --------------------------------------------------------------------- |
  | `bar`         | comparing items                                | grouped (or stacked) columns                                          |
  | `hbar`        | comparing items with long labels               | bars across, each label beside its row (stacks too)                   |
  | `line`        | change over time                               | lines with ringed markers                                             |
  | `area`        | change over time when the total matters        | washed bands (stacks too)                                             |
  | `combo`       | a volume and a rate on one axis                | the first series as bars, the rest as lines                           |
  | `scatter`     | how two measures move together                 | points; categories that read as numbers are the x axis                |
  | `radar`       | one profile over 3-12 criteria                 | a web with one closed shape per series; outside 3-12 it draws as bars |
  | `funnel`      | stages that narrow                             | centred stages of the first series with each one's share of the first |
  | `gauge`       | one value against a maximum (and a target)     | a half dial per category of the first series (at most six)            |
  | `sparkline`   | a compact trend                                | one small line per series with its name and last value, no axes       |
  | `pie`         | shares of one whole                            | slices of the first series                                            |
  | `donut`       | shares of one whole, with the total            | a ring of the first series                                            |
  | `waterfall`   | signed changes contributing to a running total | first series increments, starting at zero; connectors between steps   |
  | `heatmap`     | intensity across a matrix                      | categories as columns, each series as one row with a common scale     |
  | `treemap`     | relative weights across categories             | flat nonnegative first-series weights as proportional areas           |
  | `histogram`   | distribution of observations                   | first-series integer counts in precomputed equal-width bins           |
  | `bubble`      | relationship between three measures            | numeric X categories, Y series, then nonnegative Size series          |
  | `boxplot`     | spread with a five-number summary              | Min, Q1, Median, Q3, Max series, ordered at every category            |
  | `candlestick` | price/open-close intervals                     | Open, High, Low, Close series with consistent bounds                  |
  | `lollipop`    | sparse signed category comparisons             | one signed series with zero-based stems and endpoint dots             |
  | `bullet`      | actual results against targets                 | nonnegative Actual then Target series on one common scale             |

- `categories`: up to 24 labels — the x axis, or the slices of a pie.
- `series`: up to six `{ name, values: number[] }`, one value per category. Values past the last
  category are kept but not drawn; a missing value draws no bar and breaks a line. Pie and donut
  plot the first series only.
- `stacked: boolean = false` stacks bars and horizontal bars (positives one way, negatives the
  other) and areas (negatives count as zero). A combo never stacks.
- `maxValue` sets the top of a gauge's dial (or a radar's outer ring); left out, it is a round
  number above the largest value. `targetValue` marks a gauge's goal across every dial, named by
  `targetLabel = 'Target'`.
- `valuePrefix` / `valueSuffix` (for example `$`, `%`, ` ر.س`) frame every printed value; axis ticks
  compact thousands (`12K`).
- `showLegend = true`, `showValues = false`, `showGrid = true`.
- `palette: 'accent' | 'mixed' | 'mono' | 'success' = 'accent'`, `height: 'sm' | 'md' | 'lg'`,
  `variant: 'card' | 'plain' = 'card'`, plus the shared section props.
- `otherLabel = 'Other'` names the slice a pie folds its smallest values into past eight slices.

Specialized charts require complete finite values for their plotted roles. Invalid specialized data
shows a visible accessible explanation instead of another chart type. Empty specialized input also
explains the required shape. These checks do not change how existing saved chart types render.
Bubble X and Size and histogram counts remain unitless; value affixes apply to bubble Y only.
Treemap zero weights remain in the key/table but occupy no area. Bullet `maxValue`, when supplied,
must include all Actual and Target values. Candle fill direction and table role headings provide
meaning beyond color. Advanced types share the complete `AdvancedChart` component contract.

Inserted from the Library, the block starts as a four-quarter, two-series bar chart.

## How it is drawn

`chart-geometry.ts` (pure: nice ticks, bar paths, line and area paths, pie and donut arcs),
`chart-format.ts` (how numbers print), `chart-kind.ts` (which type is drawn, which legend it gets)
and the models — `chart-model.ts` (bar, line, area, combo), `chart-scatter.ts`, `chart-rows.ts`
(horizontal bars and the funnel, a vertical bar chart turned on its side), `chart-polar.ts` (radar
and gauge) and `chart-spark.ts` — compute everything. `chart-plot.tsx`, `chart-hbar.tsx`,
`chart-funnel.tsx`, `chart-radar.tsx`, `chart-gauge.tsx`, `chart-sparkline.tsx`, `chart-pie.tsx` and
`chart-keys.tsx` only map those models to elements, and `Chart.tsx` frames them. None of these is in
`schema.ts`'s import chain.

`AdvancedChart/` owns the nine specialized families. `advanced-contract.ts` supplies the lightweight
type vocabulary and validation, while interval/matrix models calculate bounded normalized SVG
geometry without a runtime chart dependency. Schema discovery never imports those render models.

- **Size.** A bar, line or area plot is as wide as its column and as tall as `height` says (`h-48`,
  `h-64`, `h-80`): the SVG stretches to that box (`preserveAspectRatio="none"`), so a chart in a
  wide column does not grow tall. Everything that must stay thin or round is drawn with a
  non-scaling stroke.
- **Marks.** Bars are capped in width, rounded at their data end and square at the baseline, with a
  2-unit gap between grouped bars and stacked segments. Lines are 2px, line markers are round dots
  with a ring in the ground colour, area fills are a wash. Gridlines are hairlines in the section's
  ink at low opacity, with a stronger zero line. A pie or donut keeps its square proportions.
- **Text in HTML.** Tick labels, category labels, value labels and the legend are HTML laid over the
  SVG by percentage, so they stay crisp at any size and never mirror. Text wears text tokens, never
  the series colour; a swatch beside each name carries identity.
- **RTL.** On an RTL page the SVG mirrors (`rtl:-scale-x-100`), so the first category sits at the
  inline start, horizontal bars grow from the inline start, a radar runs anticlockwise and a gauge
  fills from the right; the HTML labels follow the page direction on their own
  (`inset-inline-start`, never `left`). A funnel is symmetric. A negative number keeps its minus
  sign in front through a left-to-right isolate.
- **Rows.** Horizontal bars and funnel stages sit in equal rows (`1fr` rows size to the tallest
  label), so a long label wraps and every row grows together; the SVG stretches over them.
- **Colour.** A palette is an ordered list of theme roles — `accent`, `success`, `text-muted` and
  `current` (the section's own ink) — with opacity steps. Adjacent slots alternate hue and neutral.
  No hex value exists anywhere in the block; re-pointing the theme repaints every chart.
- **Crowding.** Past 40 value labels only the last category is labelled; past eight categories the
  axis keeps every second (past sixteen, every third) label once the container narrows; past eight
  positive values a pie folds the smallest into one `otherLabel` slice.
- **Hover without script.** Every bar, marker and slice carries an SVG `<title>` with its category,
  series and value.

## Accessibility

The SVG is one named image (a gauge's or sparkline's row of small pictures is one `role="img"`
element around them). The numbers behind it are a visually hidden `<table>` — one row per category
with a row header, one column per series with a column header — so a screen reader can read the data
instead of a picture of it. The visual axis and value labels are `aria-hidden` because the table
carries them. Legend items stay readable as a list.

## Parts

Each inner element is a part (block-parts DESIGN §1), editable on the canvas, styled through
`partStyles` and addressable by the agent. The numbers are Inspector rows: a value is a number, not
text to edit in place.

| name           | kind | bind            | label (en / ar)                          |
| -------------- | ---- | --------------- | ---------------------------------------- |
| `title`        | text | `title`         | Title / العنوان                          |
| `description`  | text | `description`   | Description / الوصف (multiline)          |
| `categories`   | list | `categories`    | Categories / الفئات                      |
| `category`     | text | `categories.*`  | Category / الفئة                         |
| `series`       | list | `series`        | Data series / السلاسل                    |
| `dataset`      | item | `series.*`      | Series / السلسلة                         |
| `otherLabel`   | text | `otherLabel`    | Other slice label / تسمية الشريحة الأخرى |
| `dataset.name` | text | `series.*.name` | Series name / اسم السلسلة                |
| `valuePrefix`  | text | `valuePrefix`   | Value prefix / بادئة القيمة              |
| `valueSuffix`  | text | `valueSuffix`   | Value suffix / لاحقة القيمة              |
| `targetLabel`  | text | `targetLabel`   | Target label / تسمية الهدف               |

Category labels sit on the x axis of a bar, line, area or combo chart, beside the rows of a
horizontal bar chart or funnel, around a radar, under each gauge and in the legend of a pie or
donut; series names sit in the legend (which a single-series chart does not draw) or beside each
sparkline. A scatter whose categories are numbers shows them as its x axis instead, and a gauge's
target label is one part shown on every dial, hosted by the first. The value prefix and suffix are
one part each, printed beside every number: the lowest axis tick (for a pie, the legend's first
value, else the donut total; for a funnel, gauge or sparkline, the first value; for a radar, its
innermost ring) hosts the in-place editor. On the canvas the screen-reader table and the SVG
tooltips are left out — each would be a second, unbound copy of a label being edited — and the
published page keeps both.

## Limitations

- A gauge's dial starts at zero; a negative value draws an empty dial. It draws at most six dials.
- Sparklines are each scaled to their own range: they compare shapes, not sizes.
- A radar plots a missing or negative value at its centre.
- A scatter's x values come from its category labels; labels that are not all numbers place the
  points over the category bands instead.
