# Image

A publish-safe image primitive for site, store, and docs surfaces. A newly dropped block may have no
source yet; the editor canvas shows setup guidance while preview and published output stay empty.

## Props

| Prop         | Type                                         | Default      | Notes                                      |
| ------------ | -------------------------------------------- | ------------ | ------------------------------------------ |
| `src`        | `string` (≤2000)                             | none         | Optional URL; no source publishes nothing. |
| `alt`        | `string` (≤160)                              | `''`         | Never inferred from `src` or a filename.   |
| `decorative` | `boolean`                                    | `false`      | Forces `alt=""` and suppresses warnings.   |
| `fit`        | `'cover' \| 'contain' \| 'fill'`             | `'cover'`    | Maps directly to `object-fit`.             |
| `ratio`      | `'auto' \| 'square' \| 'wide' \| 'portrait'` | `'auto'`     | Auto, 1:1, 16:9, or 3:4.                   |
| `radius`     | `'none' \| 'sm' \| 'md' \| 'full'`           | `'none'`     | Theme-scaled corner treatment.             |
| `width`      | `'narrow' \| 'standard' \| 'wide' \| 'full'` | `'standard'` | Never exceeds the parent column.           |
| `align`      | `'start' \| 'center' \| 'end'`               | `'start'`    | Uses logical alignment for RTL.            |
| `background` | colour role                                  | none         | Visible behind `contain` and placeholders. |
| `textColor`  | colour role                                  | none         | Colours canvas-only guidance.              |

## Accessibility

Decorative images render only an empty alternative (`alt=""`) and expose no generated label.
Informative images preserve the authored `alt` exactly. If an informative image has empty alt text,
the canvas shows a visible warning; preview and published pages never render that editor guidance.
The block never manufactures alternative text from the URL or filename.

## Pictures from the site's library

`asset` holds either a reference into the site's asset table or a **labelled absence** — an object
carrying the sentence explaining why there is nothing here. There is no third state, and in
particular no generated address: an agent that could write a `src` could write a plausible-looking
URL that satisfies every schema, stores, validates, renders, and is a broken image on a stranger's
site. `src` remains for a person typing a URL they own.

When both are set and the asset RESOLVES, the asset wins — the site's table outlives someone else's
URL. When the asset does NOT resolve, or is a labelled absence, `src` is what renders: a fallback is
better than a hole, and it is the same path a block rendered outside its site takes.

The reference is resolved through `AssetTableProvider` from `@craftkit/builder-renderer`. Three
outcomes:

| State                                    | Canvas                                                                   | Published   |
| ---------------------------------------- | ------------------------------------------------------------------------ | ----------- |
| The table resolves the id                | The picture, with the library's alt text if the block has none           | The picture |
| `{ absent, reason }`, no `src`           | The reason, in the words whoever produced the absence wrote              | Nothing     |
| An id the table cannot resolve, no `src` | `The picture "…" is not in the asset table this page was rendered with.` | Nothing     |
| Either of those **with** a `src`         | The `src`                                                                | The `src`   |

The third row should never fire on a stored site: `validateSite` refuses a site whose reference does
not resolve in its **own** table, and that table holds _copies_ of the library's entries. So a
picture deleted from the library does **not** break a site that already used it — which is exactly
why the site copies rather than resolving live. What the row does cover is a document rendered
outside its site: a page in isolation, an export assembled without the table.

With no provider mounted at all — a story, a static export — the block falls back to `src` rather
than throwing.

## Empty and loading behavior

With no `src`, the canvas renders a placeholder so an author can select and configure the block.
Outside the canvas it returns no markup. Real images use native lazy loading and asynchronous
decoding; there is no network-dependent story because the catalog uses an inline data URI.

## Sizing, themes, and RTL

Ratio and fit control the image's content box. The media always has `max-inline-size: 100%`; its
natural block size is retained in `auto` ratio. Width and alignment use logical CSS, so start/end
mirror with document direction. Background and text are theme roles rather than stored colour
literals.

## Known limitations

- The block accepts a URL string but does not upload, crop, or transform media.
- It resolves an asset reference; it does not choose one. Selection is `selectAssets` in
  `@craftkit/builder-ai`, and browsing is `AssetPicker`.
- It does not infer dimensions or alternative text.
- Broken remote URLs use the browser's native broken-image behavior.

## Parts

Each inner element is a part (block-parts DESIGN §1): selectable and editable on the canvas, styled
per part through `partStyles`, and addressable by the agent by name, alias or label. Text and link
parts carry `dir="auto"`, so an English line on an Arabic page keeps its full stop at the end. Part
markers (`data-ck-part`, `data-ck-bind`) exist on the canvas only.

| name    | kind  | bind          | label (en / ar) |
| ------- | ----- | ------------- | --------------- |
| `image` | image | `src` + `alt` | Image / الصورة  |

On the canvas the empty frame is the image part too, so a double-click on it opens the asset picker.
A library `asset` still wins over `src`.
