# PageFooter

`PageFooter` is a two-slot container for the end of a page. It owns footer presentation, while its
children own all content. Authors can delete or replace either region with text, actions,
navigation, or nested layouts without changing the footer schema. Use it once at the bottom of a
page; do not use it as a card footer or as navigation in the middle of content.

## Usage

```json
{
  "id": "page-footer",
  "type": "pageFooter",
  "props": {
    "layout": "columns",
    "bottomBar": true,
    "background": "surfaceInverse",
    "textColor": "textInverse"
  },
  "slots": {
    "default": ["footer-copy", "footer-links"],
    "bottom": ["footer-legal", "footer-social"]
  }
}
```

The ids in each slot refer to ordinary child blocks in the document. Content is never stored in a
footer-specific `brand`, `statement`, link-column, social, or legal property.

## Slots

| Slot      | Allowed child blocks                       | Purpose                                                |
| --------- | ------------------------------------------ | ------------------------------------------------------ |
| `default` | `richText`, `cta`, `navLinks`, and `stack` | The main footer body.                                  |
| `bottom`  | `richText`, `cta`, `navLinks`, and `stack` | The region that usually holds legal or social content. |

Both slots accept any number of the listed blocks. Use `stack` when a region needs a nested row,
column, or group of blocks.

## Properties

| Prop         | Type and default                                            | Purpose                                                            |
| ------------ | ----------------------------------------------------------- | ------------------------------------------------------------------ |
| `layout`     | `columns \| centered \| split` = `columns`                  | Arranges the two slots while they share the main flow.             |
| `bottomBar`  | `boolean` = `false`                                         | Moves `bottom` into its own row under a rule.                      |
| `border`     | `none \| top` = `none`                                      | Adds an outer logical block-start border.                          |
| `align`      | `start \| center \| end` = `start`                          | Sets logical alignment for the inner content.                      |
| `background` | `surface \| surfaceInverse \| accent` (optional)            | Page colour role; deliberately unset so `tone` decides by default. |
| `textColor`  | `text \| textInverse \| textMuted \| accentText` (optional) | Page text role; deliberately unset so `tone` decides by default.   |
| `tone`       | `transparent \| light \| dark` = `transparent`              | Supplies the section colour treatment when roles are not selected. |
| `spacing`    | `none \| sm \| md \| lg` = `lg`                             | Token-backed logical block spacing.                                |
| `width`      | `narrow \| standard \| wide \| full` = `wide`               | Maximum inline size of the footer content.                         |

All properties except `bottomBar` appear on the design tab. `bottomBar` appears under advanced
structure because it changes the slot's DOM placement.

## Variants and states

- **Default** renders populated body and bottom slots in the main columns flow.
- **Split** lets both regions claim their natural share and wrap as space narrows.
- **BottomBar** moves only the bottom slot into a ruled row beneath the body.
- **InverseColour** demonstrates page-owned colour roles, not literal colours.
- **CanvasEmpty** shows distinct body and bottom drop hints. Preview and published rendering never
  include those hints.

## Accessibility

The root is a semantic footer landmark. Slotted blocks retain their own semantics, accessible names,
native links, and keyboard behavior; the container does not rewrite them. On the canvas, an empty
slot is exposed as a named status hint so the two drop regions are distinguishable. Those hints are
authoring scaffolding and are omitted whenever `isCanvas` is false.

## RTL, responsive, theme, and content behavior

Layout uses logical properties and logical alignment, so the same document mirrors with its content
direction. Columns and split layouts wrap instead of forcing the two regions below their usable
minimum. Every measurement and colour comes from a page-owned `--t-*` token. The footer never uses
editor chrome tokens and never applies link, heading, or paragraph styling to arbitrary slotted
children.
