# Report

One dataset as a report section: a title that states the finding, a summary, up to eight KPI cards
computed from the data, one accessible chart, and an optional table of the numbers. It is what the
agent's `report.build` tool inserts from pasted rows, and it renders with no client script.

## When to use it

Use it when one table of numbers deserves a section of its own — monthly sales, bookings by quarter,
a conversion funnel. Use a `chart` for a picture alone, a `table` for text or exact values alone,
and `stats` for headline numbers that do not come from one table.

## Content model

- `title` (default "Quarterly report") and an optional `summary`. The title names the section and
  the chart; the summary describes the chart.
- `dataNote` is optional source or preparation context (1–320 characters), such as original
  observation count and histogram bin definitions. It renders as a readable paragraph by the chart
  and contributes to its accessible description independently of the authored summary. A blank
  stored note is hidden, allowing a changed chart type to clear obsolete preparation details.
- `categories`: up to 24 row labels (the first column). `series`: up to six numeric columns, each
  `{ name, values }` with one number per category.
- `valuePrefix` / `valueSuffix` print beside measures in cards, chart and table. Observation-count
  cards are unitless even when other values use a currency or percentage.
- `kpis`: up to eight `{ label, series, measure, better }` cards. `series` is the column's index;
  `measure` is `last` (default), `total`, `average`, `max`, `min`, `median` or `count`. A `last`
  card also shows the change against the row before: an arrow, the signed percentage and
  `changeLabel` ("vs previous"). `better: 'up' | 'down'` says which way is good — revenue up, costs
  down.
- Each KPI optionally accepts `comparisonValue` for a supplied baseline of the same aggregation and
  unit, `target` for its goal threshold, and `detail` (up to 120 characters) for methodology or
  period context. Explicit baselines override the previous-row comparison even when zero. They use
  the optional `comparisonLabel` (default display: "vs baseline") and visibly include the actual
  baseline number with the measure's units. Count baselines stay unitless. `changeLabel` remains
  reserved for comparisons against the previous source row; changing it never relabels an explicit
  baseline. A zero baseline retains its caption and number but shows no invalid percentage.
- `showTrends` is off unless `true`; enabled cards show their own series in source order, trimmed to
  the visible categories. Counts have no trend because the source values are not counts of
  observations. No source values are invented.
- `chartType` supports Chart's complete enum, including `gauge`, `sparkline`, `waterfall`,
  `heatmap`, `treemap`, `histogram`, `bubble`, `boxplot`, `candlestick`, `lollipop` and `bullet`.
  Each specialized type requires Chart's documented series shape; choosing a type does not invent
  OHLC values or quantiles. `maxValue`, `targetValue` and `targetLabel` forward to the chart.
  `stacked`, `showLegend`, `showValues`, `showGrid`, `palette`, `height` and `otherLabel` match
  Chart.
- `showTable = true`, `variant: 'card' | 'plain' = 'card'`, plus the shared section props.

## How it is drawn

`report-model.ts` computes each card's number and change and decides which element hosts a label
printed in several places; `report-kpis.tsx` and `report-table.tsx` draw the cards and the table,
and the chart is drawn by the Chart block's own figures (`Chart/chart-figure.tsx`), so a report's
chart is exactly a Chart. Numbers past 100,000 shorten on a card (`$145.7K`); the table prints them
in full.

- **Change and colour.** The arrow (▲ ▼ –) and the sign carry the direction for everyone. A change
  the `better` way wears the success role; a worsening keeps the ink, because no theme role means
  "bad"; a flat change is muted. No colour is ever the only signal.
- **Cards.** A card variant draws each card and the chart on the surface, with the ink set on their
  children so a dark section stays legible; the plain variant draws a hairline at each card's inline
  start instead.
- **RTL.** Cards and the table follow the page direction; the chart mirrors exactly as the Chart
  block does. Signed percentages sit in a left-to-right isolate so the sign stays in front.

## Accessibility

The section is a region named by its title. The chart is one image named by the title and described
by the summary. The table is a real table — a row header per category, a column header per column —
inside a focusable group named by the title so a keyboard can scroll it. Without the table, the
chart's visually hidden data table carries the numbers instead. KPI arrows are hidden from screen
readers; the signed percentage is read.

A label printed in several places is one part with one host for the in-place editor: the table hosts
the categories and column names (the chart, without a table); the first card with a number hosts the
value prefix and suffix (else the table, else the chart); the first card with a change hosts the
change label. The first explicit-baseline card independently hosts `comparisonLabel`. The first card
with a target hosts `targetLabel`; otherwise the chart hosts it. The other copies show the committed
text.

## Limitations

- Without an explicit comparison baseline, only a `last` card compares with the row before it. A
  zero baseline yields no percentage; it never becomes infinity. Aggregates with nonfinite results
  render an unavailable value, never a fabricated valid number.
- Target text includes the actual threshold (`≥` for a minimum, `≤` for a maximum) and a distinct
  met/unmet symbol. For positive targets and nonnegative actual values, the percentage is **actual /
  target**, not an inferred success score. Lower-is-better metrics can meet the target below 100%;
  the inequality and status make that distinction explicit. The bar stops at 100 but visible and
  accessible text retains the full percentage, including 120% or higher. Zero or negative targets
  retain the threshold and status without an invalid ratio.
- Median sorts a copy and averages the middle pair for even observations. Count includes only
  observations in the selected series within the available category range; no observations means
  zero. Table order is preserved. Raw data should already have the intended chronological order.
- The cards read columns by index: reordering `series` moves what a card shows.

## Examples across domains

Financial Goals shows revenue, a spending ceiling, median revenue and unitless observed-month count.
Project Delivery shows completed work items and sprint targets. Marketing Mobile RTL shows Arabic
weekly analytics with the same source feeding cards, trends, chart and table. All examples are
illustrative and require actual user data before publication.
