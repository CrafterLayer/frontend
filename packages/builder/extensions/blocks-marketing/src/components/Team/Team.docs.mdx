# Team

A production-ready people section for leadership, studio, and company pages. `cards` is the most
visual layout, `editorial` gives every biography more room, and `compact` works for dense rosters.

## Content model

- `eyebrow?: string (1–40)`
- `heading: string (1–80) = 'Meet the team'`
- `body?: string (1–240)`
- `members (≤12)` contain a name, role, and optional biography, portrait, alt text, and profile URL.
- `profileLabel: string (1–40) = 'View profile'` localizes the repeated profile action.
- `variant: 'cards' | 'editorial' | 'compact' = 'cards'`
- `columns: '2' | '3' | '4' = '4'`

The standard shared section controls provide alignment, tone, spacing, width, token colour roles,
motion, typography, logical padding/margins, gutter, and validated utility classes.

## Accessibility and responsive behavior

The section is labelled by its visible heading and the people are a semantic list. A supplied
portrait uses its authored alt text; an image without alt text is decorative because the adjacent
name already identifies the person. Initials are also hidden from assistive technology. Profile
links include the member name in their accessible label. Container queries collapse every layout
inside the actual space allocated by the builder, independent of viewport width, and all spacing
uses logical or token-bound utilities for RTL safety.

## Parts

Each inner element is a part (block-parts DESIGN §1): selectable and editable on the canvas, styled
per part through `partStyles` (a part's name styles every instance; `name@2` styles the third one
and wins), and addressable by the agent by name, alias or label. Text and link parts carry
`dir="auto"`, so an English line on an Arabic page keeps its full stop at the end.

| name           | kind  | bind                                        | label (en / ar)                   |
| -------------- | ----- | ------------------------------------------- | --------------------------------- |
| `eyebrow`      | text  | `eyebrow`                                   | Eyebrow / الشارة                  |
| `heading`      | text  | `heading`                                   | Heading / العنوان                 |
| `body`         | text  | `body`                                      | Body / الوصف (multiline)          |
| `members`      | list  | `members`                                   | People / الأشخاص                  |
| `member`       | item  | `members.*`                                 | Person / الشخص                    |
| `member.name`  | text  | `members.*.name`                            | Name / الاسم                      |
| `member.role`  | text  | `members.*.role`                            | Role / المنصب                     |
| `member.bio`   | text  | `members.*.bio`                             | Bio / النبذة (multiline)          |
| `member.image` | image | `members.*.imageSrc` + `members.*.imageAlt` | Portrait / الصورة                 |
| `profileLabel` | text  | `profileLabel`                              | Profile link text / نص رابط الملف |

`profileLabel` is one value shown in every profile link, so it is one top-level part: while it is
edited in place the first link holds the editor and the others keep the stored text. Each link is
named by `aria-labelledby` over its visible label and the person's name, never a string built from
them. A link's destination (`profileHref`) is edited in the person's row in the Inspector.
