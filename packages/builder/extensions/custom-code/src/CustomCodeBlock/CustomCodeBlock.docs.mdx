# CustomCodeBlock

The assistant's escape hatch, as a block: a region whose **shape is authored per request** instead
of chosen from the catalog.

<Canvas of={CustomCodeBlockStories.Default} />

Everything else the product ships is a registered block with a fixed prop vocabulary, and that is
what makes a document editable, validated and undoable. It is also what bounds the design space: a
request the catalog has no shape for — "a CV page with a diagonal timeline" — had no answer except
the nearest section that already exists. This block is the answer, and it gives up none of those
properties: it stores a **tree**, so the document stays JSON, the door still validates every write,
and undo still moves one node.

## One node, not dozens

A generated section could be expanded into many real document nodes. That was rejected for v1: it
multiplies the undo history for one user action, and it turns "regenerate this section" into a diff
across dozens of nodes rather than one prop write. One node also states the truth plainly in the
layers tree — this region was authored, and it is edited as a unit.

## What this file owns

Only two things: the stored props, and the stylesheet that belongs to this one region. The walk
itself lives in the renderer package as
[`CustomCode`](?path=/docs/builder-renderer-customcode--docs), because the tolerant read, the depth
ceiling and component resolution are rendering concerns shared by the canvas and the static export.

## The stylesheet is scoped, and scoped completely

<Canvas of={CustomCodeBlockStories.Styled} />

Every selector is prefixed with the hosting node's `[data-ck]` attribute before it is written, so
one region's CSS cannot reach into another's — or into the editor chrome around it. Colours go
through `var(--t-accent)` so the page still re-themes.

## A refused stylesheet is dropped whole, and said out loud

<Canvas of={CustomCodeBlockStories.RefusedOnCanvas} />

One rule the policy refuses and **nothing** in the sheet applies. That is the right thing to publish
and the wrong thing to hide. The first live user hit exactly this: an external image URL the
sanitizer of the day refused, and every other rule vanished with it, silently — an unstyled panel
and no reason anywhere.

So the canvas says why, in the same voice `UnknownBlock` uses, naming the rule that was refused.

<Canvas of={CustomCodeBlockStories.RefusedWhenPublished} />

The published page never carries the note. A visitor cannot act on it, and a page that explains its
own chrome to a reader is talking to the wrong person.
