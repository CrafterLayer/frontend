# InlineRichText

The rich editing surface used INSIDE the canvas (milestone B3c, US1/US2) — the SAME B3b editor in
inline chrome, never a second engine. Where `RichTextField` is the inspector's field (block toolbar,
panel styling), `InlineRichText` is the canvas seam's surface: no toolbar (the floating text bubble
replaces it), typography inherited from the block it edits, and a selection channel that reports
presence, semantics, and a deferred anchor source. It stays inside the one package allowed to depend
on the editing engine, so the containment law (engine loads lazily, published path engine-free) is
untouched.

## Commit law

Inherited from `RichTextEditor`, not reimplemented: every editor update calls `onCommit` exactly
ONCE with the engine JSON projected onto the stored whitelist; mounting, exiting, and external
re-seeds call it zero times. Document truth holds both ways — an incoming `value` that is not this
surface's own last emission (undo, redo, another surface's write) re-seeds the editor without a
commit, and a host that refuses a commit leaves the editor reconciled back to the stored value.

## The selection channel

`onSelectionChange` reports a non-null `{ measure }` source when the current selection is eligible
for formatting, or `null` when it is not. It fires on every selection update, after every
transaction, on focus and blur, and once with `null` on unmount. Reporting itself reads no geometry:
the canvas places `measure` in its plain-TypeScript anchor channel, which invokes only the latest
source during one frame-coalesced flush. React holds only selection semantics and actions, never
per-frame rectangles.

When invoked by that flush, `measure` returns `{ box, rects }`, structurally the shell's
`FloatingAnchor`, in FRAME-viewport coordinates (the editor's own document; layer-local is
preview-local). It re-checks `shouldShowBubble`, so a selection that collapsed before the flush
returns `null`. `rects` carries one box per selected line, so a multi-line selection lets the bubble
hug the first or last line instead of the union box. Reusing the same live source on scroll or
reflow keeps the bubble glued to the selection and lets the host hide it outside the visible area.

Both halves are reimplemented TipTap bubble-menu logic (MIT, attributed in the source and in
`vendor/VENDOR.md`): `selectionAnchorOf(editor)` and `shouldShowBubble(editor, menuElement?)` are
exported for the deferred source's flush-time measurement and visibility checks.

## Usage

On the canvas this surface is resolved from the REGISTRY, not imported: the extension contributes a
lazy `inlineEditors` entry whose module (`./inline-editor`) adapts this component to the schema's
`InlineEditorProps` — commit/exit/anchor pass through, and an `onActions` channel reports the
formatting actions (bold, italic, link, bulleted list, numbered list, clear) for as long as the edit
owns focus, a collapsed caret included (Link is disabled there), so the shell can keep its formatting
bar beside the editor without ever importing the engine. The anchor still follows `shouldShowBubble`:
at a bare caret it is `null`, and the canvas docks the bar at the editing surface. Direct use looks like this:

```tsx
import { InlineRichText } from '@craftkit/builder-richtext';

<InlineRichText
  label="Article body"
  value={node.props.body} // document truth
  onCommit={(next) => kernel.dispatch('setProp', { id, key: 'body', value: next }, 'user')}
  onExit={endInlineSession} // Escape
  onSelectionChange={(report) =>
    anchorChannel.setText(
      report === null ? null : 'measure' in report ? report.measure : () => report,
    )
  }
  formattingMenuElement={bubbleHost} // stable host keeps the bubble alive during cross-document blur
  requestFormattingMenuFocus={focusFirstCanvasFormattingAction}
/>;
```

## API

| Prop                         | Type                                              | Notes                                               |
| ---------------------------- | ------------------------------------------------- | --------------------------------------------------- |
| `value`                      | `unknown`                                         | stored rich-text JSON (document truth)              |
| `onCommit`                   | `(next: RichTextDoc) => void`                     | ONE call per editor update                          |
| `onExit`                     | `() => void`                                      | Escape pressed inside the surface                   |
| `onSelectionChange`          | `(report: SelectionAnchorReport \| null) => void` | presence + deferred geometry; `null` = hide         |
| `formattingMenuElement`      | `Element \| null`                                 | canvas-owned focus boundary for the formatting menu |
| `requestFormattingMenuFocus` | `(restore: () => void) => boolean`                | forward-Tab bridge to the first enabled host action |
| `label`                      | `string`                                          | accessible name for the editing surface             |
| `onEditorReady`              | `(editor: Editor) => void`                        | dev/test instrumentation, once per editor           |

`SelectionAnchorReport` is either the current `{ measure }` source or the additive legacy
`SelectionAnchor` geometry form. First-party editors always report the source. `measure()` returns
`{ box, rects }` of `{ x, y, width, height }` boxes — per-line `rects`, union `box`, all
frame-viewport relative — and must be called only by a coalesced anchor-channel flush.

## Accessibility & RTL

The contenteditable surface is a named (`label` via a visually hidden element), multiline textbox
with `dir="auto"`, so mixed ar/en prose follows its own direction (see the RTL story). The surface
suppresses the UA outline exactly as the field does, and the inline root replaces it with a
`:focus-within` ring — a focus indicator is always visible. Escape leaves without committing; the
event is not swallowed, so the host's frame-level gesture handling stays authoritative. When a
canvas supplies `formattingMenuElement`, focus inside that host remains part of the editing context;
focus leaving both the surface and that host closes the anchor channel. An unmodified forward Tab is
intercepted by a native capture listener before ProseMirror keymaps and requests the first enabled
host action. The canvas confirms whether focus moved; a failed request leaves Tab native. Shift+Tab
or Escape from the bubble calls a TipTap-owned `EditorView.focus()` bookmark, so the unchanged
ProseMirror selection is restored without a formatting transaction. Escape in the editor continues
to end the inline session.

## When not to use

- Inspector editing belongs to `RichTextField` — it brings the block toolbar and panel chrome.
- Rendering stored rich text belongs to the zero-dependency `RichText` component — never mount an
  editor on the read path.
- Plain-text inline properties belong to the shell's `InlineTextSurface` — no engine involved.

## Known limitations

- The surface renders no formatting controls of its own: without a host-wired bubble, formatting is
  keyboard shortcuts only (Cmd/Ctrl-B, -I, the engine's defaults).
- A host-wired bubble must pass its stable portal host as `formattingMenuElement`; otherwise a blur
  is genuine focus loss and hides the bubble.
- Anchor coordinates are frame-viewport; hosts outside the canvas frame must project them themselves
  (the canvas shell already does).
