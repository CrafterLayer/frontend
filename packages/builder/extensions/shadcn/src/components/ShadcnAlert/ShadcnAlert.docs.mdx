# Alert

A callout that says something the reader needs to notice. Adapted from shadcn/ui.

<Canvas of={AlertStories.Info} />

## Severity is not only a colour

Upstream ships `default` and `destructive`, and the difference between them is a text colour. That
is a message a colour-blind reader receives as "a message" — the severity, the most important thing
about an alert, arrives through the one channel some people do not have.

Here the variant also changes what the element **reports**:

| Variant     | Role     | Behaviour                            |
| ----------- | -------- | ------------------------------------ |
| `info`      | `status` | Waits for a pause before announcing. |
| `attention` | `status` | Same, with a stronger outline.       |
| `critical`  | `alert`  | Interrupts.                          |

Getting this backwards is how a page ends up shouting a hint over whatever the reader was doing.
Colour is the third signal, after the role and the glyph.

## The body takes blocks

The same argument the Card makes. An alert whose body is a string holds a sentence; a real one holds
a sentence **and a link to the thing that fixes it**.

## Parts

Each inner element is a part (block-parts DESIGN §1): selectable and editable on the canvas, styled
per part through `partStyles`, and addressable by the agent by name, alias or label. Text and link
parts carry `dir="auto"`, so an English line on an Arabic page keeps its full stop at the end. Part
markers (`data-ck-part`, `data-ck-bind`) exist on the canvas only.

| name    | kind | bind    | label (en / ar) |
| ------- | ---- | ------- | --------------- |
| `icon`  | box  | —       | Icon / الأيقونة |
| `title` | text | `title` | Title / العنوان |
