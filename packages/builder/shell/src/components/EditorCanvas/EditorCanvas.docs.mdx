# EditorCanvas

The builder's live canvas: the isolated preview frame plus selection chrome, keyboard traversal,
drag editing, a selected-block action bar, and B3c inline editing at the block's own text seam.

## Usage

```tsx
import { EditorCanvas, createBuilder, lightTheme } from '@craftkit/builder';

<EditorCanvas kernel={kernel} theme={lightTheme} />;
```

The kernel arrives **by prop**. Clicking a block calls `kernel.setSelection([id])` — selection made
programmatically or by any other surface renders identically, because the chrome draws FROM kernel
state (single source of truth).

## The zero-render law

Pointer movement, hovering, selecting, and clearing cause **zero document-content re-renders**.
React renders this component's scaffold once; the hot path lives in plain TypeScript machinery that
positions prebuilt chrome elements directly, batched to the display's frame rhythm. Opening or
closing an inline edit reaches only the named node through a stable node-keyed subscription; it does
not replace the seam prop across all 1,000 stress nodes.

## API

| Prop            | Type                      | Notes                                                                                                                                                                        |
| --------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kernel`        | `BuilderKernel`           | required; by prop                                                                                                                                                            |
| `theme`         | `Theme`                   | forwarded to the preview frame's token variables                                                                                                                             |
| `title`         | `string`                  | accessible name (default "Editor canvas")                                                                                                                                    |
| `onToolError`   | `(toolId, error) => void` | canvas-tool failures are contained here                                                                                                                                      |
| `geometryPorts` | `Partial<GeometryPorts>`  | test-only injection (jsdom has no layout)                                                                                                                                    |
| `onBlockRender` | `(nodeId) => void`        | test/dev instrumentation (zero-render proofs)                                                                                                                                |
| `editable`      | `boolean`                 | B2b drag editing; absent ⇒ B2a byte-compatible                                                                                                                               |
| `onDragHandle`  | `(handle) => void`        | receives the external-insert entry point                                                                                                                                     |
| `frameWidth`    | `number`                  | B3a device emulation: narrows + centers the frame shell (the overlay layer shares its origin, so chrome stays aligned with zero coordinate translation); absent ⇒ full width |
| `zoom`          | `number`                  | visual scale (default `1`); does not change `frameWidth` or the selected responsive breakpoint                                                                               |

`frameWidth` remains the exact authored device width even when the editor column is narrower; the
canvas scrolls instead of changing the page breakpoint. `zoom` changes only the visual footprint,
and the frame bridge converts pointer coordinates back into authored pixels. Invalid widths or zoom
values fall back safely. Pass `breakpoint` alongside `frameWidth` so the content renders the same
bucket the inspector edits.

The frame is `100 / zoom` percent tall so the scaled frame fills the column, which makes its own
viewport — what `vh` measures — taller at every step of zoom-out. The canvas therefore publishes
`--ck-vh` on the frame root (one hundredth of the frame's height at zoom 1), and custom-code regions
read their viewport heights through it (`canvasViewportHeightUnits`): a region at `min-height: 70vh`
has the same height at "Fit · 57%" as at 100%, and the same proportions as in Preview, where nothing
is set and the real `vh` applies.

## Accessibility

The canvas host is a focusable named region. Arrow keys traverse siblings (Down/Up) and step
into/out of slots (Right/Left, mirrored under RTL content); Escape clears — from the host itself or
from any non-editable chrome inside it (the block action bar), but never from an editable element
(input, textarea, select, contenteditable) and never for an Escape a nearer handler already claimed.
While an authored element inside a composed region is focused (see below), the first Escape steps
out to the region and the second clears. Focus returns to the host first, so the chrome that held it
can unmount with the selection. Three more ways out exist because clicking the page background
INSIDE the frame selects the document root on purpose (page-level props live in the Inspector): a
click on the gutter around the frame or on the host's own surface, the bar's last action, Deselect
(`Esc` on its tooltip), and the Inspector's `Clear selection` — all through
`kernel.clearSelection()`, never a transaction. During a rich inline selection, ordinary forward Tab
crosses the iframe boundary to the first enabled formatting action in the host bubble. Shift+Tab
from that first action or Escape from anywhere in the bubble returns to the editor with its
selection intact; Escape in the editor then exits to the canvas host. If the bubble has no enabled
action, Tab is not cancelled, so chrome never becomes a focus trap. A polite live region announces
`<name> selected` / `Selection cleared` — the dependable channel across the frame boundary — while
outlines carry the visible name label.

## Composed regions: addressing what the assistant wrote

A block whose renderer draws a custom-code tree on the canvas stamps every authored element and icon
with `data-ck-path` (its child-index path from the tree root; a published page never carries it).
The index's `hitAt` reads it alongside `data-bldr-node`, so the pointer resolves to the node AND,
inside such a region, to the element under it. A click there calls `kernel.focusElement(id, path)` —
one ephemeral write that selects the region and focuses the element — and the selection outline
wraps that element with its own name (`Image`, `Heading`, `Button`, `Icon (mail)`), measured lazily
through `elementRect` on the same observation channel. Hover follows the element under the pointer
the same way. The live region announces `<element> in <region> selected`. A focus the canvas cannot
resolve (edited away, never stamped here) degrades to the region rather than vanishing. Canvas
tools, drag sessions, keyboard traversal and the block action bar keep working at node granularity:
clicking the portrait and pressing Delete deletes the region, as the bar's own label says. Component
references inside a tree are not addressable yet.

## Drag editing (`editable`)

With `editable`, pressing the selected block's dedicated grip and moving at least 8px starts a drag
session — ghost outline, valid-target highlight, and an insertion indicator that flips before/after
with the pointer half (an empty container is targetable through the middle band). Pressing page text
or another context action never arms structural movement. The session is pure chrome until the drop:
exactly ONE `moveNode`/`insertNode` transaction on commit, byte-identical zero-trace on cancel
(Escape, no-target release, or the node vanishing mid-drag). Slot rules (allow lists, `max` with the
own-slot exemption, never-into-own-subtree) gate targets at resolution time and provably agree with
the command door. `Alt+Arrows` performs the same moves without a pointer; the palette hands insert
payloads into the same session through `onDragHandle`. Without `editable`, none of this machinery
exists — B2a behavior is byte-compatible.

## Inline editing (`editable`)

Double-click a declared inline-editable value, press Enter on its selected block, or choose **Edit
text** from the action bar. Entry is view state and dispatches nothing. Pointer entry retains the
gesture coordinates so the caret opens at the clicked character; keyboard entry opens at the logical
end.

Contributed rich editors are resolved before the block swaps to an editing surface. While the lazy
editor is loading, the block keeps its ordinary rendered output, so a built-in editor never mounts
only to be replaced. If the contribution fails to load, the built-in surface becomes the one chosen
fallback and the failure is reported through `onToolError`.

Rich-selection geometry is measured from the live frame selection on every observer-driven anchor
flush. No rectangle is retained in React state, so the formatting bubble follows scroll and reflow
and hides when the selection is no longer visible. While a RICH edit is open the formatting bar
stays beside the editor (block-parts, 2026-10-06): over the selection when there is one, docked at
the editing surface while the caret is collapsed. The editor still decides which actions exist and
which are enabled (the contributed editor offers bold, italic, link, bulleted and numbered lists and
clear formatting; the built-in surface disables its marks at a bare caret), and the canvas names
them in the editor's language (`richTextLabels`, default from `canvasLabels.locale`). A rejected
`setProp` keeps the draft and session open and renders the door's message next to the editing
control through `aria-describedby`.

Focus uses the same ownership split as formatting: the frame-side editor intercepts only an
unmodified forward Tab and supplies an editor-specific selection bookmark; the shell finds and
focuses the first enabled host-side action. The editor cancels Tab only after the shell confirms the
move, and owns restoration. This keeps the shell engine-free while making the ordinary sequential
navigation gesture work across two documents.

The selected-block bar contains duplicate, delete, move earlier, move later, and conditionally
**Edit text**. The last action is present only when the block declares an inline target and opens
the session directly; it deliberately does not enter the structural action dispatch path.

## RTL and theming

Chrome geometry is measured (physical) and therefore direction-proof; a live `dir` flip reflows the
content and the observer channel repositions the chrome. Chrome colors read shell-owned `--bldr-*`
custom properties with fallbacks, independent of the document's `--t-*` theme.

## The Arabic editor and screen sizes

`canvasLabels` (`EDITOR_CANVAS_LABELS_AR`) and `elementNameWords` (`ELEMENT_NAME_WORDS_AR`) put the
selection chip, the Selection and Gesture announcements and the action bar's name in Arabic; block
chips use the Arabic block-name catalogue. A new `frameWidth`/`breakpoint` keeps the selection and
scrolls it into view in the frame: at a narrower width the page reflows taller, and an element
picked on desktop otherwise sat far below the fold with its outline and quick bar hidden.

## Element chrome (P7, style-manager DESIGN.md §A.6, §A.7, §E)

Every element inside a custom-code region is a widget on the canvas.

- **Quick bar.** With an element focused, `ElementQuickBar` replaces the block action bar, anchored
  ABOVE the element (flipping below when clipped) on the same anchor channel the bar uses —
  scrolling renders nothing. Its actions are tree commands on the element, never the region (the old
  `block-actions.ts` bug: Delete removed the whole region). `Alt+F10` enters the bar; Escape there
  returns to the element.
- **Selection.** A click focuses the element under the pointer; a LOCKED element passes the click
  (and the hover) to its parent. Shift-click toggles the element in the shared multi-selection
  (`elementSelection`, P2), drawn with extra outlines; the quick bar writes every member in one
  transaction. Enter steps into the first child (or into a region's tree), Shift+Enter to the
  parent.
- **Parts a parent draws.** A tab trigger is the tab panel's `label` part drawn by Tabs
  (`data-ck-part-owner`). Double-click or Enter types on the trigger itself
  (`overlay/in-place-text-edit.ts`): React's nodes are swapped out for an editing span and put back
  before the write, Enter or blur commits ONE labelled part transaction (one Undo), Escape cancels,
  and Space is typed rather than activating the button.
- **In-place text.** Double-click or Enter on a text element opens it for typing
  (`contenteditable="plaintext-only"` on its own canvas DOM). Enter or blur commits ONE
  `patchTreeNode {text}`; Escape cancels with no trace. Selecting a range shows the text bubble:
  bold, italic, underline, highlight, link (an address prompt), larger, accent colour — each one
  `formatTreeText`, written together with any pending typing as one transaction.
- **Spacing handles.** Padding and margin bands per logical side over the focused element. A drag
  previews by swapping classes on the canvas DOM only, snaps to the spacing scale with a value
  badge, and commits once on release (Shift = all sides, Alt = the opposite pair).
- **Positioned elements.** An absolute/fixed element is dragged directly: the preview is a DOM
  translate, snapping (6px) to its parent's and siblings' edges and centres with guide lines; the
  release writes `inset-s` / `inset-bs` through the engine. Arrow keys nudge it 1px (Shift 10px),
  the inline arrows mirrored on an RTL page.
- **Tree drops.** The drag session also carries tree payloads: `beginTreeInsert` (the Library panel)
  and the quick bar's grip (a move). The tree drop resolver finds the container under the pointer
  and the seat along its axis (RTL-aware), drawing the insertion line and the edges the siblings
  share; the drop is one `insertTreeNode` or `moveTreeNode`.
- **Forced state.** `styleState` other than `default` stamps `data-ck-state` on the focused element
  (on its `.group` ancestor for group-hover); the canvas's live compiler must be created with
  `canvasStateVariants: true` for the stamp to show.
- **Grid tracks.** `activeSector === 'layout'` draws the focused grid's column and row tracks.
- **Shortcuts.** Frame keydowns the canvas does not claim go to `onShortcut` (focus inside the
  iframe never reaches host listeners); editable targets are skipped.

New props: `elementSelection`, `styleBucket`, `styleState`, `activeSector`, `onOpenStyleSector`,
`onEditWithAi`, `onSaveTemplate`, `onAnimate`, `onReplaceMedia`, `onShortcut`, `styleClipboard`,
`palette`, `namedStyles`, `namedStyleClasses`, `quickBarLabels`, `treeTextLabels`,
`elementNameWords`, `editorDir`, and the test-only `treeDropPorts`. `CanvasDragHandle` gains the
optional `beginTreeInsert(node, label, x, y)`.

## Block parts (block-parts DESIGN §2.6, §2.7, §2.14)

Every inner element of a **registered** block — the hero's badge, heading, paragraph, buttons and
meta line, each feature card and its title — is a **part** the block declares in its schema
(`parts`) and stamps on the canvas with `blockPartProps` (`data-ck-part`, `data-ck-part-index`,
`data-ck-bind`; canvas only, never in the published HTML). The canvas treats parts the way it treats
authored elements, the GrapesJS way:

| Input                | With                       | Result                                                                 |
| -------------------- | -------------------------- | ---------------------------------------------------------------------- |
| hover                | any                        | a thin outline on the part and a chip "Heading · Hero" (localized)     |
| click                | a part                     | `kernel.focusPart(nodeId, ref)` — the block is selected too            |
| click                | the block outside parts    | the whole block; the part focus clears                                 |
| double-click / Enter | text, rich or link part    | the inline editor opens at the part's bind; Enter or blur commits ONCE |
| double-click / Enter | image part                 | `onReplacePartImage(target)` — the host's asset picker                 |
| Enter                | list or item part          | steps into its first part; Shift+Enter steps back out                  |
| Escape               | any                        | inline edit → part → block → parent → nothing, one layer per press     |
| Delete / Backspace   | item part                  | removes the item (`planPartListOp`), focus moves to its neighbour      |
| Alt+↑ / Alt+↓        | item, or a part inside one | moves the item; the block itself never moves                           |
| Tab / Shift+Tab      | a part                     | the next / previous part in document order; at either end Tab leaves   |

- **Hit testing.** `rectIndex.hitAt` returns `part` only when the part's nearest node wrapper is the
  hit node, so a part inside a nested child block belongs to that child. A custom-code
  `data-ck-path` keeps precedence. `partRect(id, ref)` measures one instance (cached per version).
- **One write, one Undo.** Inline commits go through `partInlineCommit` (`planPartValue`), the quick
  bar through `createPartBarModel` (`planPartStyle` in tokens mode into the block's `partStyles`
  prop), and item actions through `performPartAction` (`planPartListOp`, `planPartDir`) — every
  write is one labelled `dispatchGroup`.
- **Quick bar.** With a part focused, `ElementQuickBar` (part model, `quickGroupsForPart`, the part
  action row and `PartLinkPopover` for a link's text and address) replaces the block action bar,
  anchored to the part. It never shows over an open inline editor. Attribute-only groups (direction,
  motion, hover preset) are not offered on a part; Direction is a part action (Auto / LTR / RTL) and
  "This item only" switches the style scope of a repeated part.
- **Announcements.** The selection region reads "Heading in Hero selected" / «حُدِّد العنوان في
  البطل»; item actions are announced in the editor's language.

New props: `onReplacePartImage(target)`, `onOpenPartStyle(sector, target)`,
`onEditWithAiPart(target)` (names fixed by DESIGN §2.13; the playground wires them) and `linkPages`
(the link popover's page picker). `EditorCanvasLabels` gains the optional `locale` and
`partNotEditable`.
