# EditorCanvas

The builder's live canvas: the isolated preview frame plus selection chrome, keyboard traversal,
drag editing, a selected-block action bar, and B3c inline editing at the block's own text seam.

## Usage

```tsx
import { EditorCanvas, createBuilder, lightTheme } from '@craftkit/builder';

<EditorCanvas kernel={kernel} theme={lightTheme} />;
```

The kernel arrives **by prop**. Clicking a block calls `kernel.setSelection([id])` — selection made
programmatically or by any other surface renders identically, because the chrome draws FROM kernel
state (single source of truth).

## The zero-render law

Pointer movement, hovering, selecting, and clearing cause **zero document-content re-renders**.
React renders this component's scaffold once; the hot path lives in plain TypeScript machinery that
positions prebuilt chrome elements directly, batched to the display's frame rhythm. Opening or
closing an inline edit reaches only the named node through a stable node-keyed subscription; it does
not replace the seam prop across all 1,000 stress nodes.

## API

| Prop            | Type                      | Notes                                                                                                                                                                        |
| --------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kernel`        | `BuilderKernel`           | required; by prop                                                                                                                                                            |
| `theme`         | `Theme`                   | forwarded to the preview frame's token variables                                                                                                                             |
| `title`         | `string`                  | accessible name (default "Editor canvas")                                                                                                                                    |
| `onToolError`   | `(toolId, error) => void` | canvas-tool failures are contained here                                                                                                                                      |
| `geometryPorts` | `Partial<GeometryPorts>`  | test-only injection (jsdom has no layout)                                                                                                                                    |
| `onBlockRender` | `(nodeId) => void`        | test/dev instrumentation (zero-render proofs)                                                                                                                                |
| `editable`      | `boolean`                 | B2b drag editing; absent ⇒ B2a byte-compatible                                                                                                                               |
| `onDragHandle`  | `(handle) => void`        | receives the external-insert entry point                                                                                                                                     |
| `frameWidth`    | `number`                  | B3a device emulation: narrows + centers the frame shell (the overlay layer shares its origin, so chrome stays aligned with zero coordinate translation); absent ⇒ full width |

Known limitation: `frameWidth` caps at 100% of the host (`maxInlineSize`), so on a viewport narrower
than the chosen width the visual frame is narrower than the editing bucket's width — the bucket
follows the CHOSEN width (intent), not the measured one. Invalid widths (0, negative, NaN) fall back
to full width. Pass `breakpoint` alongside `frameWidth` so the content renders the same bucket the
inspector edits.

## Accessibility

The canvas host is a focusable named region. Arrow keys traverse siblings (Down/Up) and step
into/out of slots (Right/Left, mirrored under RTL content); Escape clears; Tab is never trapped. A
polite live region announces `<name> selected` / `Selection cleared` — the dependable channel across
the frame boundary — while outlines carry the visible name label.

## Drag editing (`editable`)

With `editable`, pressing a block and crossing a 4px threshold starts a drag session — ghost
outline, valid-target highlight, and an insertion indicator that flips before/after with the pointer
half (an empty container is targetable through the middle band). The session is pure chrome until
the drop: exactly ONE `moveNode`/`insertNode` transaction on commit, byte-identical zero-trace on
cancel (Escape, no-target release, or the node vanishing mid-drag). Slot rules (allow lists, `max`
with the own-slot exemption, never-into-own-subtree) gate targets at resolution time and provably
agree with the command door. `Alt+Arrows` performs the same moves without a pointer; the palette
hands insert payloads into the same session through `onDragHandle`. Without `editable`, none of this
machinery exists — B2a behavior is byte-compatible.

## Inline editing (`editable`)

Double-click a declared inline-editable value, press Enter on its selected block, or choose **Edit
text** from the action bar. Entry is view state and dispatches nothing. Pointer entry retains the
gesture coordinates so the caret opens at the clicked character; keyboard entry opens at the logical
end.

Contributed rich editors are resolved before the block swaps to an editing surface. While the lazy
editor is loading, the block keeps its ordinary rendered output, so a built-in editor never mounts
only to be replaced. If the contribution fails to load, the built-in surface becomes the one chosen
fallback and the failure is reported through `onToolError`.

Rich-selection geometry is measured from the live frame selection on every observer-driven anchor
flush. No rectangle is retained in React state, so the formatting bubble follows scroll and reflow
and hides when the selection is no longer visible. A rejected `setProp` keeps the draft and session
open and renders the door's message next to the editing control through `aria-describedby`.

The selected-block bar contains duplicate, delete, move earlier, move later, and conditionally
**Edit text**. The last action is present only when the block declares an inline target and opens
the session directly; it deliberately does not enter the structural action dispatch path.

## RTL and theming

Chrome geometry is measured (physical) and therefore direction-proof; a live `dir` flip reflows the
content and the observer channel repositions the chrome. Chrome colors read shell-owned `--bldr-*`
custom properties with fallbacks, independent of the document's `--t-*` theme.
