# Inspector

The generated properties panel for the selected builder block. The block schema owns the editable
properties and their information architecture; the Inspector owns tabs, collapsible sections,
controls, validation feedback, responsive overrides, and commits through the kernel door.

## Declaring tabs and sections

`BlockSchema.propertyGroups` is an optional map whose keys are checked against that schema's actual
`props` keys. Each entry chooses one fixed tab and may name a section:

```tsx
const textBlock = defineBlockSchema({
  type: 'text',
  description: 'Editable text block.',
  props: z.object({
    text: z.string().default('Text'),
    font: z.string().default('Inter'),
    align: z.enum(['start', 'center', 'end']).default('start'),
    responsive: z.boolean().default(true),
  }),
  propertyGroups: {
    text: { tab: 'content', section: 'Content' },
    font: { tab: 'design', section: 'Typography' },
    align: { tab: 'design', section: 'Alignment' },
    responsive: { tab: 'advanced', section: 'Responsive' },
  },
  examples: [],
});
```

The tab union is exactly `'content' | 'design' | 'advanced'`. A misspelled property key or tab is a
TypeScript error. Existing blocks need no migration: **every property with no declaration defaults
to the Content tab**. If an entry declares a tab but omits `section`, its section label defaults to
that tab's visible label (`Content`, `Design`, or `Advanced`).

The Inspector iterates the real props shape and then looks up each declaration. It never creates a
row from metadata and never infers a tab, section, pair, or control kind from a property's name, Zod
type, or responsive bucket. This keeps the strip honest even when declarations are partial.

## Declaring a page colour role

A colour-bearing property uses the same keyed declaration and adds `kind: 'color-role'`. The
property name is irrelevant; a string named `color`, `colour`, `paint`, or anything else remains an
ordinary field until the block declares the kind explicitly.

```tsx
const card = defineBlockSchema({
  type: 'card',
  description: 'A themed card.',
  props: z.object({
    paint: z.enum(['surface', 'surfaceInverse', 'accent']).default('surface'),
  }),
  propertyGroups: {
    paint: { tab: 'design', section: 'Color', kind: 'color-role' },
  },
  examples: [],
});
```

The picker offers the renderer palette's complete role list. Every option carries the role's human
name and uses the active page theme's resolved value for its swatch. Choosing an option writes only
the role string through `setProp` or `setResponsive`; the resolved colour value never crosses the
document door. The block renderer consumes that role as its matching `--t-*` custom property, so a
theme change can repaint the page without rewriting any block.

The Zod property remains the persisted-value authority. A block should constrain it to the roles it
can render; if it declares a narrower subset than the shared palette, choosing an unsupported role
is rejected by the ordinary door and the reason stays on that row with no transaction.

## Declaring a paired grid

The optional `pair` declaration belongs on **each** of the two properties that form a compact grid.
It supplies the stable pair identity, one shared heading, and the cell caption; the Inspector never
guesses a partner from names such as `marginTop` and `marginBottom`.

```tsx
propertyGroups: {
  marginTop: {
    tab: 'design',
    section: 'Spacing',
    pair: { id: 'margin', label: 'Margin', cellLabel: 'Top' },
  },
  marginBottom: {
    tab: 'design',
    section: 'Spacing',
    pair: { id: 'margin', label: 'Margin', cellLabel: 'Bottom' },
  },
}
```

A valid pair has exactly two properties with the same non-empty `id`, in the same resolved tab and
section, with the same pair label and different cell labels. The pending schema-side
`BlockPropertyGroup.pair` contract will validate that authoring rule; until it lands, the Inspector
defensively keeps a missing or malformed declaration as ordinary rows; unpaired properties in the
same section remain full-width rows.

Block authors declare content copy and arrays under Content; layout, spacing, alignment, width, and
tone under Design; and structural or escape-hatch values under Advanced. A tab with no declared or
defaulted rows is omitted instead of opening an empty panel.

## Information hierarchy

Only tabs containing real rows render. Every populated tab always has its `tabpanel` shell (so
`aria-controls` resolves), but a tab's BODY — its sections and rows — mounts on the tab's first
activation and then stays mounted, hidden, for as long as the same block and bucket are selected.
Selecting a block therefore pays for the Content rows only; the first visit to Design or Advanced
pays for that tab's rows once. After that first visit a round trip costs nothing, and rejection
reasons, unsent nested drafts, lazily loaded contributions, and focus locks all survive it. A new
selection or bucket resets the strip to Content and remounts the rows under new keys. Sections
retain schema property order, use first occurrence for section order, start expanded, and collapse
independently through buttons with `aria-expanded` and `aria-controls`. Declared pairs retain that
property order inside their two-cell grid.

The professional story declares these sections:

- **Typography** — Font, Weight, Size, Line height, and Letter spacing;
- **Alignment** — a compact icon segmented control;
- **Color** — the declared page-role group, with one truthful swatch and human name per role;
- **Spacing** — declared Margin and Padding pairs in a two-by-two grid, plus any unpaired rows;
- **Width** — a full-width numeric control with a unit suffix; and
- **Responsive** — a labelled switch.

## Field layout and presentation

### Visual hierarchy

The panel is sized by its container. `.bldr-inspector` fills the column it is placed in
(`inline-size: 100%; min-block-size: 100%`), draws no seam of its own and reads no width token: the
shell's aside decides the column and paints the one hairline between canvas and inspector (the
Palette and LayersTree precedent). Stories supply that frame through the `withInspectorFrame`
decorator; the two canvas stories opt out and wrap their own `<Inspector>` in the token-sized box.

The head is sticky against the scrolling aside, so the strip stays reachable while a long block's
rows scroll beneath it. Inside it, **Inspector** is the eyebrow — a muted, uppercase caption, the
LayersTree title idiom — and the block's display name is the visible title: the same string as the
canvas chip and the layers tree (`blockDisplayName`), one line, elided, in
`<p aria-label="Selected block">`. The bucket badge sits beside the name as a small accent pill;
under an override bucket a soft accent note reads `Editing tablet overrides` below. With nothing
selected the name reads `No block selected` in the muted weight, and the body shows a dashed,
centred invitation with the pointer mark in a soft accent disc. An unregistered type is not "nothing
to edit": it says what happened in the warning tone with a thick leading edge, the same strip a
rejection wears in the danger tone.

The tab strip is a segmented control on the panel's control ground (the Palette idiom): the selected
tab lifts onto the panel colour with the raised shadow, the rest sit muted until hovered. Sections
are separated by one hairline between neighbours — never under the last, never per row — and rows
breathe through the section grid's gap instead. A section heading is a small uppercase toggle with
one chevron glyph that points down when expanded and is rotated 180° when collapsed
(`[data-collapsed='true']`), which reads the same under RTL. A declared pair is one legend and two
cells whose captions are quieter than a full row's label, because the legend already named the pair.

### Scale tokens

Three tokens size every control, and no Inspector rule names a size of its own:

- `--bldr-control-height-sm` (density-aware) — tabs, section toggles, the block name's line,
  repeater disclosures;
- `--bldr-control-height` (density-aware) — text and number inputs, the repeater's Add button;
- `--bldr-control-sm` — the story-measured squares: icon segments, the device-override glyph box,
  the override-clear button, repeater actions, and the Clear-selection ChromeButton (`size="sm"`).

Under `data-bldr-density="compact"` the first two shrink with the rest of the chrome; the
`CompactDensity` story measures it.

### Edges, glyphs, motion, dark

Every hairline is `var(--bldr-border-hairline)` and every thick edge (rejection, warning) is
`var(--bldr-border-thick)`; no sheet spends a spacing token on a border. Every glyph carries the
shared recipe on the element — `viewBox="0 0 16 16"`, `fill="none"`, `stroke="currentColor"`,
`stroke-width="1.5"`, round caps and joins — and CSS only sizes its box, never its stroke. Each
sheet that declares a transition carries its own `@media (prefers-reduced-motion: reduce)` block on
top of the product-wide zeroing. Dark chrome is the same rules under different token values: no
Inspector sheet branches on `data-bldr-theme`, and the `DarkChrome` story proves the selected tab
and the panel ground resolve to the dark `--bldr-panel`. Logical properties only, so RTL mirrors by
construction. The focus ring is never clipped: the segments container and the repeater card do not
hide overflow; pressed and hover fills carry their own logical end radii, and repeater chrome stays
transparent over the card's rounded border. `Inspector.design.test.tsx` reads the three sheets and
pins every rule above.

### Controls

Every property label sits above its control. Native and contributed controls receive the complete
row width in the resolved Inspector column instead of sharing it with a fixed label column. The
visible label is humanized while the established property key remains the control's accessible name.

- Text, select, switch, number, and read-only fallbacks retain their established behavior.
- Numbers show a unit suffix; dimension-like values use `px`, durations use `ms`, angles use `deg`,
  and other numbers show an explicit unitless dash. Numeric values use the builder mono face and
  tabular numerals; the unit is a sunken end cap on the same control.
- A property declared as `kind: 'color-role'` renders the role radiogroup. An undeclared string
  remains the ordinary text control regardless of its name.
- Enums with three or more supported alignment or direction members render as icon segments. Each
  segment is exactly `var(--bldr-control-sm)` in both axes, never a stretched fraction of the row,
  and exposes its selection through `aria-pressed`.
- Booleans remain native labelled inputs with `role="switch"` and a tokenized switch skin.
- Arrays render as repeaters; unsupported non-array schemas remain accessible read-only values.
- A declared pair renders one `fieldset`/`legend` heading and two labelled cells. The visible
  `Top`/`Bottom` captions come from the declaration; each control keeps its original property key as
  its accessible name.
- An owned override wears the `{bucket} override` pill — the same pill as the header's bucket badge
  — beside a small, quiet clear button that turns to the danger tone only under the pointer.

All component styling reads the `--bldr-*` theme contract. The Inspector declares no fallback
colors, sizes, spacing, radii, or motion values.

## Repeater arrays

Every array element renders as a collapsible card. For object elements, the card label uses the
first non-empty required string in schema declaration order, then the first non-empty declared
string, then `Item N`. This yields `title` for Features, `name` for Pricing, and `quote` for
Testimonials. Primitive strings, including `Pricing.plans[].features`, label themselves.

The card body is not a separate form implementation. It sends every object property or primitive
element back through `InspectorRowBody`, and a nested array recurses into another repeater through
the same path. Add builds a valid starting element from schema defaults and required
scalar/object/array shapes. Empty arrays state `No items yet.` and keep Add visible.

Add, Remove, Move Up, and Move Down each rebuild the root array immutably and call the existing
property commit door once. Text and number descendants keep a local draft while typing and commit
the rebuilt array once on blur or Enter. Array minimum and maximum bounds disable the corresponding
controls with a visible reason. Door refusals stay on the nested row or repeater action that caused
them, while the document remains unchanged.

## Editing inside a composed region

A block whose schema declares a composition tree (`customCodeTree()` — the assistant's `customCode`
block is the one that ships) stores everything the assistant authored in ONE prop of ONE node: the
portrait, the headline, the buttons. That is the right storage shape and, on its own, the wrong
editing shape — selecting the region offered `label`, a JSON textarea, and `css`, and a person who
clicked the photo could not touch the photo.

The kernel now carries an ephemeral **element focus** beside the selection (`state.elementFocus`,
set by `kernel.focusElement(id, path)` when the canvas hit-tests an authored element, cleared by
`clearElementFocus()`, `setSelection()`, `clearSelection()`, or the host node vanishing). While a
focus names an element of the selected node, the Inspector replaces the block's tabs with that
element's rows:

- the header names the element as a person would (`Image`, `Heading`, `Link`, `Button`,
  `Icon (mail)`), says which region it is in, and offers **Back to region**;
- an `img` edits `src` and `alt`; any text-bearing tag edits `text`; a link adds `href` and
  `target`; a `time` adds `datetime`; every element edits `className` under Design and `id`,
  `title`, `role`, `aria-label`, `aria-hidden` under Advanced; an icon edits its `name`, `label`,
  `size`, `strokeWidth`, and classes;
- every commit rebuilds the tree prop at the focused path and dispatches ONE `setProp` — one
  transaction, one undo, structural sharing everywhere else. Clearing an attribute deletes the key
  (never stores `''` or `undefined`), so the document stays JSON and a cleared `title` does not
  render;
- values render from document truth: the panel subscribes to the tree prop, so an undo or an AI
  rewrite shows through, and an element that no longer exists says so and offers the way back.

The prop is found by its declaration, never by name (`customCodeTreeKey`), and the row vocabulary
mirrors the tree's own (`custom-code/element-fields.ts`), so the panel never offers a value the
validated door refuses. Component references inside a tree (`{kind:'component'}`) are not
addressable yet: they render through the referenced block's own root.

## Defaults and document truth

`effectiveValue` resolves a row from the stored document value first and otherwise asks its Zod
schema for the declared default. That is why a newly added defaulted property displays the value the
block promises instead of an empty dash in an older document. The same effective base value is used
for responsive inheritance; an absent responsive override still means “inherit,” never “write the
default into the override bucket.”

Every committed change is exactly one kernel dispatch: `setProp` in the base bucket and
`setResponsive` under tablet/mobile. A repeater descendant still writes the complete top-level array
through that same door; it never gains a nested mutation path. Undo, redo, and external writes
therefore flow back from document truth. A value rejected by validation changes nothing; its reason
appears immediately after the control, joins that control's `aria-describedby` chain, and is
announced by the named polite live region.

## Responsive buckets

With `bucket="tablet"` (or `"mobile"`) the same declared tab and section structure remains in place.
A badge identifies each owned override, its clear button removes the override in one transaction,
and inherited base values appear as placeholders for text/number or effective values for
select/switch controls. Only values vary by breakpoint. Every root property row also carries the
non-interactive screen glyph named `Supports device overrides` before an override exists, so the
capability is visible without claiming an override was already made. Repeater descendants do not
receive that glyph because they commit through their root array row.

## Extensible field types

An explicit declared kind resolves first, because block-owned semantics must not change with
registration order. For properties without one, resolution consults registered field-type
contributions: the highest `match(schema)` score wins, ties break by registration order, and
components load lazily through the per-definition cache. A contribution that fails to load or throws
falls back to the default control for that one property. A focused row keeps its resolved renderer
until focus leaves, so runtime registration cannot steal a caret mid-edit.

A contributed component also receives the editor `locale` and the host's `assetLibrary`. A field
type may declare two more things (`FieldTypeDef`):

- `siblings: true` — the row receives the block's other props (`FieldProps.siblings`: key, schema
  and base value), so the field finds what it needs by its schema's marker, never by a prop name.
  Only such a row subscribes to its node's `props`; every other row keeps its single-property
  subscription.
- `hidden` — the Inspector leaves the prop out: no row, and no section or tab when nothing else is
  in it. `true` hides it always (data another surface writes, such as the Studio's `jsMeta`); a
  function `({ value, siblings }) => boolean` hides it per value (the customCode Scene settings with
  nothing to tune). The panel reads the hidden keys as one primitive, so a value edit renders it
  only when a row appears or disappears; only props a hiding field type matches are resolved for
  this. A rule that throws keeps the row.

## Render model

The panel is built so that one property edit renders one row. The shell subscribes to the kernel
through four primitive selectors — the selected id, its block type, its `label` prop, and the
document direction — plus the registry epoch and the (immer-stable) element focus. A store write
that changes none of those (every value edit, undo, redo, or an edit to another block) never renders
the Inspector, its header, its tabs, or its live region.

Each row is an `InspectorPropertyRow`, the panel's single `memo` boundary. It subscribes to its own
property through `store.subscribeNode` with three primitive reads (the stored value, the bucket's
override, and whether an override exists) and renders `InspectorRowBody`, a plain function. A write
to another key of the same node runs those reads and bails; a write to this key renders this body
once. Sections are controlled `memo` components: a toggle renders the panel and the toggled section,
and every other section and row bails on unchanged props.

Everything a row needs besides its own value travels in one memoised `scope` object — kernel, node
id, bucket, catalog version, palette, `onRetheme`, `announce`, direction, declarations. A new scope
identity is exactly the set of events that must touch every mounted row once: a selection or bucket
change (rows remount under `${nodeId}:${bucket}:${propKey}` keys), a registry epoch (rows re-resolve
their field type), a theme or direction change. `onRetheme` is wrapped so a host that re-creates it
on every render does not pay for that, and it stays `undefined` when the host passes `undefined` so
the colour control keeps hiding its picker.

Schema facts are cached per schema identity in module `WeakMap`s: the default value (one
`safeParse(undefined)` per schema, ever — every consumer treats that value as immutable) and the
enum members with their segmented-control classification. Announcements go through a per-panel
external store whose only subscriber is the live region, so a commit's message renders that element
alone. A nested deferred draft is keyed by the value it was typed over and simply stops applying
when that value moves, so the edited row body runs exactly once per edit.

`Inspector.render-count.test.tsx` pins this contract with real render counters: nine Content rows on
mount, one body per external edit, zero header/section/live-region renders on an edit, zero renders
on a tab round trip, one section on a collapse, header-only on a host rerender with identical props,
and zero commits for unrelated-node, same-id-selection, and no-op writes.

## Accessibility and keyboard behavior

While a block is selected, the title row carries a quiet, small `Clear selection` button beside the
panel title (the cross glyph is decorative; the text is its one accessible name). It calls
`kernel.clearSelection()` — the same ephemeral door the canvas uses, never a transaction, so Undo
keeps meaning "put my edit back" — returns the panel to its invitation, and announces
`Selection cleared` through the panel's polite region. With nothing selected there is nothing to
clear, so no control is offered.

The strip uses `role="tablist"`, `role="tab"`, and `role="tabpanel"`. Exactly one rendered tab has
`aria-selected="true"` and `tabIndex={0}`. Left/Right arrows move and activate with wraparound; Home
and End move to the first and last populated tab. Under a right-to-left document the arrows are
mirrored, so ArrowLeft always moves towards the next tab as drawn and ArrowRight towards the
previous one. Every panel is labelled by its controlling tab through `aria-labelledby`. The
component never emits `aria-current="page"` because these are property views, not page navigation.

Every control slot is a structural named group. Native controls connect to the visible property
label with `htmlFor`; composite segments use the label ID through `aria-labelledby`. Rejections and
responsive badges share the control's description chain. Logical properties preserve the same
ordering and sizing in RTL.

The role picker is a real radiogroup with one sequential tab stop. Left/Up and Right/Down arrows
move and select with wraparound; each radio's accessible name contains the role's human name. The
swatch is decorative and hidden from the accessibility tree. A rejected choice leaves the stored
radio checked and associates the visible reason with the radiogroup.

The device-override glyph is a sibling of the field label, not part of its label or description
chain. It has the accessible name `Supports device overrides`, and cannot change a field's name,
value, or commit behavior.

Repeater cards use disclosure buttons with `aria-expanded` and `aria-controls`. Add, Remove, Move
Up, and Move Down are native buttons; Enter and Space reorder without a drag gesture, and focus
follows the moved item. Card-local collapse and feedback state follows that same item through the
reorder. Disabled bound controls reference the visible minimum or maximum reason, while a rejected
structural action describes only its causing control and card.

## Story states

- `EmptyState` keeps the selected-block area visible with an invitation.
- `ClearSelection` presses the title-row control and proves the panel returns to that invitation
  with the kernel's selection empty and no transaction recorded.
- `DeclaredPropertyTabs` proves the declaration-backed semantics and labelled panel.
- `AllSectionsExpanded` visits all three populated tabs and their declared sections.
- `LabelAboveFullWidthControl` measures label/control geometry and the Spacing two-by-two grid in
  Chromium, including a declared pair and an unpaired Spacing row.
- `SegmentedAlignmentControlScale` measures each segment against the resolved small-control token in
  Chromium.
- `DeviceOverrideCapability` measures the breakpoint glyph against the small-control token and
  checks its 16-unit, `currentColor`, 1.5-stroke SVG idiom in Chromium.
- `RepeaterControlScaleAndFit` proves the real nested Pricing repeater stays inside the Inspector
  column and every interactive control resolves within the accepted compact-control height range.
- `ColorRolePaletteReflectsToCanvas` proves each swatch resolves, the group fits the Inspector token
  width, one role transaction lands, and the rendered block's resolved background changes.
- `RightToLeft` also proves the keyboard model under `dir="rtl"`: ArrowLeft on the Content tab
  selects and focuses Design, then the play returns to Content so reruns stay idempotent.
- `CollapsedSection`, `InvalidValueRefusal`, `TabletOverrides`, and `ContributedField` retain the
  behavioral and state variants.
- `UnknownBlockType` selects a block whose type no registered schema describes: the head still names
  it and the body says what happened in the warning tone, with no strip.
- `DarkChrome` renders the panel under `data-bldr-theme="dark"` and proves the selected tab and the
  panel ground resolve to the dark `--bldr-panel` — the same sheet, different tokens.
- `CompactDensity` renders under `data-bldr-density="compact"` and measures every tab against the
  resolved `--bldr-control-height-sm` and the text input against `--bldr-control-height`.
- `TabletOverrideMarker` proves the override vocabulary in Chromium: the `tablet override` pill on
  the owned `title`, the `Clear title override` button at `--bldr-control-sm` in both axes, one
  transaction to clear, then the override written back so reruns stay idempotent.
- `ElementFocus` renders a composed region beside the real canvas with its portrait focused: the
  header reads `Image` in the region, the image's `src`/`alt` rows are the panel, and **Back to
  region** returns the region's own rows with the selection kept.

## When not to use

This is not a general form library. It edits exactly the selected block's schema properties through
the kernel door. App-owned settings use their own forms; custom property editors contribute a field
type.

## The Arabic editor

`locale="ar"` switches every string the panel draws or announces to Arabic through one set,
`INSPECTOR_LABELS_AR` (`inspectorLabelsFor(locale)`): the region, its tabs and tablist, the empty
states, "selection cleared", and the NAME of the selection — a registered block from the Arabic
block-name catalogue (`بطاقة`, not "Card"), an element from the Arabic element words (`عنوان`).
The tab arrows follow the direction the strip is drawn in (the nearest `dir` above it), so an Arabic
editor mirrors them even over an English page. A block's own property labels come from its schema
and stay as the block author wrote them.

## Known limitations

- One node is edited at a time; a multi-id selection uses the first id.
- Under an override bucket, select/switch controls show the effective value. Pinning an override
  equal to the base takes a change away and back; text/number controls express inheritance with a
  placeholder.
- Unit presentation is limited to the property meanings already carried by property keys; unknown
  numeric meanings use the explicit unitless dash.
- Rich-text leaf properties retain their separately owned editor contract.
- Inside a composed region, only authored elements and icons are addressable; a referenced block
  (`{kind:'component'}`) still edits as part of the region. Element rows always edit the base value:
  a composition tree has no per-device overrides.

## Parts of a registered block

When the kernel's `partFocus` names a declared part of the selected block (a click on the hero's
heading, a feature card's title, a Layers part row), the panel becomes the **part panel**
(`InspectorPartPanel`): the header reads "Heading · Hero", **Back to block** clears the part focus,
Content shows only that part's bound rows, and Design is the style manager over `partSource` with a
This item / All items switch for repeated parts and a Text direction control. See the
InspectorPartPanel docs.

`assetLibrary` (an `AssetLibraryPort`) is handed to every field through `FieldServicesProvider`, so
image and asset fields pick from the host's catalogue; without it they fall back to URL entry.

## Block presets and style classes

A registered block's Design tab opens with a **Block presets** heading over the block's own schema
options (variant, background, padding…), and the style panel follows under **Style classes**. The
classes override the presets on that element. The two layers are named so that one property never
looks like two competing controls. The style panel's sticky header (screen size, state, search) sits
under the Inspector's sticky head, using the `--bldr-inspector-head-size` variable that
`InspectorHeader` sets.
