The browser fixture proves, in real Chromium + WebGL: the rig changes pose while its root keeps its
layout position; weather prefills and a spell adds particles, a ring and floating text; the dialogue
box announces each full line, accepts choices, applies variables and reaches an ending with no
horizontal overflow; the Ink story compiles in the page and plays through the same box with
variables; the tilemap pipe is added to the already-running renderer, the hero runs on the level
under keyboard input, and removing the region destroys the stage. Under reduced motion the fx calls
are no-ops, the ticker stays stopped and dialogue lines appear whole.

The StoryBiblePanel was also checked in the running playground (Vite dev server, Arabic RTL): seeded
from storage, it rendered its headings, colour swatches, remove buttons and forms, and scrolled
inside the dock.

## Not verified / limits

- Storybook browser play tests could not run in this container: the existing FactsDisclosure stories
  fail identically (browser revision mismatch with the installed Playwright). The component contract
  check, jsdom behaviour tests and live-app check cover the new panel, and the full static Storybook
  build passed (5 201 modules, 2 282 index entries; all six StoryBiblePanel stories and its docs
  page indexed).
- Full `pnpm verify`, coverage, Firefox/WebKit, real phones, screen readers and audio devices were
  not run.
- Live model output quality, latency and cost with the new skills need separately authorized
  representative evals. Local fixtures prove capability, not better generated designs.
- AssetPack, `@pixi/layout` and Spine remain deferred (T174, T176, T177).
- The Chromium used here was linked to the expected headless-shell path for local QA only; no
  repository configuration was changed for it.
